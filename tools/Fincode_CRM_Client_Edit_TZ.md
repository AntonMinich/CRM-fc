# Техническое задание: просмотр и редактирование карточки клиента

Версия: 1.0  
Дата: 26.11.2026  
Проект: Fincode — CRM и Service Desk  
Основание: `Fincode_CRM_Clients_TZ.md` (версия 1.1) и согласованный MVP-макет `Fincode_CRM_MVP.html`

## 1. Цель и границы

Дать пользователю возможность открыть созданного клиента из списка и изменить его данные: исправить, дополнить или очистить поля. Требования к обязательным полям остаются прежними.

Документ дополняет `Fincode_CRM_Clients_TZ.md`. Раздел 1 того ТЗ исключал карточку клиента и редактирование; для этих двух пунктов теперь действует настоящее ТЗ. Остальные требования, включая маску телефона и постоянное хранение в таблице «Клиенты», не меняются.

### Входит в задачу

- Открытие карточки по клику на строку списка.
- Редактирование всех шести полей: Фамилия, Имя, Отчество, Телефон, E-mail, Ответственный.
- Проверки на клиенте и на сервере.
- Сохранение изменений в той же записи таблицы «Клиенты».
- Обработка ошибок и одновременного редактирования.

### Не входит

- Удаление и архивирование клиентов.
- История изменений и журнал правок.
- Связь клиента со сделками и отдельная страница клиента с вкладками.
- Массовое редактирование.
- Автоматический поиск и объединение дубликатов.
- Права доступа по ролям.
- Дополнительные поля клиента.

## 2. Принятые решения

- Карточка открывается в модальном окне, а не на отдельной странице. Окно повторяет вид окна создания клиента. Решение согласовано заказчиком.
- Отдельного режима «только просмотр» нет: поля сразу доступны для редактирования.
- Для защиты от одновременной правки сравнивается `updated_at` записи. Если в проекте принята другая схема версий, допускается её использовать вместо этой.

| Файл | Назначение |

## 4. Открытие карточки

- Клик по любой ячейке строки клиента в списке открывает карточку.
- Заголовок окна: «Карточка клиента».
- Поля те же, в том же порядке, что в окне создания: Фамилия, Имя, Отчество, Телефон, E-mail, Ответственный. Все поля заполнены сохранёнными значениями.
- Телефон показывается по маске `+375 (XX) XXX-XX-XX`, хотя в базе хранится как `+375XXXXXXXXX`.
- Фокус при открытии переводится на поле «Имя».
- Пока карточка загружается, показывается индикатор. Если загрузка не удалась, показывается сообщение «Не удалось загрузить клиента» и кнопка «Повторить».

### Изменения в списке клиентов

В предыдущем ТЗ строка списка не была кликабельной. Теперь:

- у строки курсор-указатель; мягкая подсветка при наведении сохраняется;
- строка открывается с клавиатуры: ФИО в первой колонке оформлено как кнопка, доступна через Tab, открывается по Enter и Space, фокус виден;
- у кнопки есть доступное имя, например «Открыть карточку клиента Иванов Иван Иванович»;
- пустое состояние списка («Клиенты пока не созданы», «Клиенты не найдены») не кликабельно.

## 5. Редактирование полей

Можно изменить любое из шести полей. Очистка необязательных полей допустима, обязательные нельзя оставить пустыми.

| Поле | Обязательное | Можно очистить | Если пусто при сохранении |
|---|---|---|---|
| Фамилия | Нет | Да | Сохраняется пустое значение, в базе NULL |
| Имя | Да | Нет | «Укажите имя» |
| Отчество | Нет | Да | Сохраняется пустое значение, в базе NULL |
| Телефон | Да | Нет | «Укажите телефон» |
| E-mail | Нет | Да | Сохраняется пустое значение, в базе NULL |
| Ответственный | Да | Нет | «Выберите ответственного» |

Правила:

- Телефон работает по той же маске, что в форме создания: префикс `+375` нельзя удалить, действуют вставка из буфера, допустимые коды `17`, `25`, `29`, `33`, `44` и сообщения об ошибках из `Fincode_CRM_Clients_TZ.md`, раздел 6.4.
- Если очистить телефон до одного `+375`, поле считается пустым: сохранение блокируется, «Укажите телефон».
- E-mail при заполнении проверяется по формату: «Укажите корректный E-mail».
- Пробелы по краям текстовых значений удаляются. Регистр и знаки внутри ФИО не меняются.
- Очищенное необязательное поле не восстанавливается автоматически.
- Ответственный выбирается из списка пользователей. Сейчас доступен один: Минич Антон Андреевич.
- Если у существующей записи телефон хранится в старом формате и не распознаётся маской, в поле показывается только префикс `+375`. Чтобы сохранить карточку, номер нужно ввести заново. Пока пользователь не сохранил, прежнее значение в базе не меняется.

## 6. Кнопки и закрытие

Внизу окна справа: «Отмена» и «Сохранить». Крестик в углу работает как «Отмена».

- Если в полях нет изменений, «Сохранить» закрывает окно без запроса к серверу и без уведомления.
- «Отмена», крестик и Escape закрывают окно без изменений. Если поля были изменены, сначала спрашивается: «Закрыть окно без сохранения?».
- Нажатие на затемнённую область вне окна окно не закрывает.
- Во время отправки запроса кнопка показывает «Сохранение…» и заблокирована; закрыть окно в это время нельзя.
- После закрытия фокус возвращается на кнопку строки, из которой открыли карточку.

## 7. Сценарий сохранения

1. Пользователь меняет поля и нажимает «Сохранить».
2. Клиентская часть проверяет обязательные поля, формат телефона и E-mail.
3. При ошибках запрос не отправляется. Сообщения показываются под полями, окно остаётся открытым, фокус переходит на первое некорректное поле.
4. При корректных данных на сервер отправляется запрос обновления существующей записи.
5. Сервер повторно проверяет данные, как при создании, и допустимость ответственного.
6. Сервер обновляет ту же запись в таблице «Клиенты». Новая запись не создаётся.
7. Сервер возвращает обновлённый объект. Окно закрывается, строка в списке обновляется, появляется уведомление «Изменения сохранены».

Уведомление имеет то же оформление, что «Клиент создан». Успех показывается только после подтверждения сервера.

### Данные в базе

- Меняются только поля формы и `updated_at`, который задаёт сервер.
- `id` и `created_at` не меняются. Клиент не может их передать.
- Телефон сохраняется в нормализованном виде `+375XXXXXXXXX`.
- Очищенные необязательные поля записываются как NULL, а не как пустая строка.

### Список после сохранения

- Строка остаётся на своём месте: список сортируется по `created_at`, изменённая запись наверх не поднимается.
- Если активен поиск, он не сбрасывается. Когда после правки ФИО клиент перестал подходить под запрос, он исчезает из выдачи, уведомление всё равно показывается.

## 8. Ошибки и конфликты

- Ошибка сервера по полю — показать под этим полем; значения остальных полей не сбрасывать.
- Общая ошибка: «Не удалось сохранить изменения. Попробуйте ещё раз». Окно остаётся открытым, значения сохраняются.
- Клиент удалён или недоступен: «Клиент не найден». Окно закрывается, список обновляется.
- Одновременное редактирование: сервер сравнивает `updated_at` записи со значением, которое было при открытии карточки. Если запись уже изменена другим пользователем, изменения не сохраняются, в окне показывается сообщение «Карточка была изменена другим пользователем. Обновите данные.» и кнопка «Обновить». Она подгружает актуальные значения. Введённые правки не должны пропадать без предупреждения.
- Повторная отправка одного запроса при сетевом сбое не должна приводить к лишним изменениям. Требуется защита от повторов, как при создании.

## 9. Серверная часть

Контракт предлагаемый; согласовать с существующим API проекта.

```text
GET   /api/clients/{id}      получить карточку
PATCH /api/clients/{id}      обновить поля карточки
```

Пример тела запроса:

```json
{
  "last_name": null,
  "first_name": "Иван",
  "middle_name": "Иванович",
  "phone": "+375447574055",
  "email": "client@example.com",
  "responsible_user_id": "<идентификатор пользователя>",
  "expected_updated_at": "<значение updated_at при открытии карточки>"
}
```

- Успешный ответ: HTTP 200 и объект клиента целиком.
- Конфликт версий: HTTP 409.
- Ошибки проверки полей: HTTP 422 с указанием поля.
- Клиент не найден: HTTP 404.
- Пустые необязательные поля допускаются как `null` или пустая строка; в базе всегда хранится NULL.
- Серверные проверки идентичны проверкам при создании: имя, телефон (нормализация и допустимые коды), ответственный, формат E-mail, лимиты длины.
- Проверки доступа выполняются по существующей системе авторизации.
- Не создавать фиктивные endpoints и не заявлять их работающими, если они не реализованы.

## 10. Оформление и доступность

- Окно карточки повторяет оформление окна создания: ширина около 520 px, непрозрачный фон, скругление 16 px, затемнённая подложка.
- Обязательные поля отмечены `*`, под полями пояснение «* — обязательные поля».
- Обе темы поддерживаются. При смене темы введённые значения сохраняются.
- На узком экране окно прокручивается по вертикали, все поля и кнопки остаются доступны.
- Фокус при открытии внутри окна, Tab не уходит в фон. Ошибки и уведомления доступны скринридеру. Все действия доступны с клавиатуры.
- Данные клиента выводятся как текст, не как HTML; запросы к базе параметризованные; персональные данные не пишутся в отладочные логи без необходимости.

## 12. Критерии приёмки

- [ ] Клик по строке клиента открывает карточку с сохранёнными значениями всех шести полей.
- [ ] Строка открывается с клавиатуры, фокус виден.
- [ ] Телефон в карточке показан по маске.
- [ ] Можно изменить любое поле и сохранить; изменения остаются после обновления страницы.
- [ ] Фамилию, отчество и E-mail можно очистить, в базе они становятся NULL.
- [ ] Имя, телефон и ответственного очистить и сохранить нельзя, под полями показываются сообщения.
- [ ] Маска и проверки телефона работают так же, как при создании.
- [ ] Сохранение без изменений закрывает окно без запроса и без уведомления.
- [ ] «Отмена», крестик и Escape не меняют запись; при несохранённых правках запрашивается подтверждение.
- [ ] После сохранения обновляется та же запись, новая не создаётся.
- [ ] В базе `id` и `created_at` не меняются, `updated_at` обновляется.
- [ ] Строка в списке обновлена, порядок записей не изменился.
- [ ] «Изменения сохранены» показывается только после подтверждения сервера.
- [ ] Конфликт одновременного редактирования обрабатывается и не затирает чужие правки.
- [ ] Сервер отклоняет неверные данные, отправленные в обход формы.
- [ ] Двойное нажатие «Сохранить» не создаёт повторных изменений.
- [ ] После закрытия фокус возвращается на строку клиента.
- [ ] Всё работает в светлой и тёмной теме и на узком экране.
