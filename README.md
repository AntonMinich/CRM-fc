# Fincode — оболочка CRM и Service Desk

Базовая оболочка корпоративного приложения Fincode по ТЗ
`Fincode_CRM_Service_Desk_TZ.md`: боковое меню с двумя разделами (`CRM`,
`Service Desk`), верхняя панель, переключатель светлой и тёмной темы с
сохранением выбора и пустая рабочая область с фирменным отпечатком справа внизу.

Бизнес-функциональность (воронки, карточки, обращения, показатели, поиск,
уведомления, авторизация) в этой версии не реализована — рабочая область пустая.

## Стек

- React 19 + TypeScript, сборка Vite.
- `react-router-dom` (BrowserRouter): маршруты `/crm`, `/service-desk`, `/` → `/crm`.
- Стили — обычный CSS с токенами в `src/styles/tokens.css`, без UI-библиотек.
- Графика хранится локально в `public/assets/brand`, внешних URL нет.

## Требования

Node.js 20 или новее (проверено на Node 26.13.1, npm 11.20.0).

## Запуск

```bash
npm install       # установка зависимостей
npm run dev       # разработка: http://localhost:5173
npm run build     # проверка типов + production-сборка в dist/
npm run preview   # просмотр собранной версии: http://localhost:4173
```

`npm run dev` и `npm run preview` отдают `index.html` для любого пути
(`appType: 'spa'`), поэтому прямые ссылки `/crm` и `/service-desk` и обновление
страницы работают без дополнительной настройки.

### Публикация

Собранная папка `dist/` — статический сайт. На сервере нужен fallback на
`index.html` для клиентских маршрутов. Пример для nginx:

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

## Проверка и скриншоты

```bash
npm run screenshots   # сборка не нужна: скрипт сам поднимает vite preview
```

## Токены и поведение

- Палитра, размеры и отступы вынесены в `src/styles/tokens.css`. Значения
  `--bg-workspace`, `--bg-sidebar`, `--text-primary`, `--text-muted`, `--border`,
  `--nav-active-bg`, `--nav-active-text`, `--switch-on` взяты из раздела 8.2 ТЗ.
  Дополнительно добавлены производные токены для состояний: `--nav-hover-bg`,
  `--switch-off`, `--switch-knob`, `--focus-ring`.
- `--text-muted` в светлой теме скорректирован с `#81899C` до `#667085`:
  исходное значение даёт контраст 3.5:1 на белом фоне, что ниже требуемых 4.5:1.
  Новое значение сохраняет оттенок и даёт 4.97:1 на панели и 4.61:1 на рабочей
  области.
- Тема хранится в `localStorage` под ключом `fincode-theme` (`light` / `dark`),
  по умолчанию — светлая. Инлайн-скрипт в `index.html` применяет тему до первого
  отображения, поэтому вспышки светлого фона нет. При недоступном `localStorage`
  интерфейс продолжает работать, сохранение между сеансами не гарантируется.
- Тема задаётся атрибутом `data-theme` на `<html>` и `color-scheme`; логотип и
  декоративный отпечаток переключаются вместе с палитрой.
- Активный пункт меню помечается `aria-current="page"` (проставляет `NavLink`).
- Переключатель темы — `role="switch"` с `aria-checked`, доступное имя
  «Тёмная тема», кликабельна вся строка.
- Декор: `aria-hidden`, пустой `alt`, `pointer-events: none`, `user-select: none`,
  без анимации; рабочая область обрезает его по своим границам, поэтому прокрутка
  не появляется. Отпечаток один и тот же в обеих темах, отличается только
  непрозрачность (`--decor-opacity`: 0.30 в светлой, 0.55 в тёмной) и смещение
  (`--decor-right`, `--decor-bottom`).

## Известные ограничения

- Маршрутизация клиентская. Для production нужен fallback сервера на
  `index.html` (пример для nginx выше); при открытии `dist/index.html` напрямую
  через `file://` маршруты не работают.
- Светлая тема — последняя предложенная редакция, отдельного визуального
  согласования заказчика нет. Тёмная тема воспроизведена по согласованному
  референсу и при правках светлой не меняется.
- Отпечаток в обеих темах — один и тот же чистый знак из логотипа, без бликов,
  свечения и тёмной подложки референса. Непрозрачность: 0.30 в светлой теме,
  0.55 в тёмной. Это отступление от раздела 7.2 ТЗ (там для тёмной темы
  предполагался правый нижний фрагмент референса) — сделано по решению заказчика.
- Смещение декора задано по разделу 7 ТЗ: в светлой теме отпечаток частично
  выходит за край области (`right: -85px`, `bottom: -125px`), в тёмной прижат к
  правому нижнему углу (`right: 0`, `bottom: 0`).
- Авторизации, ролей, API и выпадающего меню аватара нет: `АМ` — заглушка.
- Проверено в Chromium, Firefox и WebKit (движок Safari) на размерах
  1440 × 900, 1280 × 800, 1024 × 768, 768 × 1024 и 390 × 844.
- В Safari обход по Tab по умолчанию не включает ссылки (настройка
  «Full Keyboard Access»); пункты меню при этом фокусируемы, активируются с
  клавиатуры и доступны через Option + Tab. Порядок обхода
  `CRM → Service Desk → Тёмная тема` проверяется в Chromium и Firefox.
- Файл палитры `photo_5460629937514551685_y.jpg` в комплект не передавался;
  использованы HEX-коды из раздела 8 ТЗ.

## Статус приёмки

Критерии раздела 12 ТЗ выполнены и проверяются автоматически командой
`npm run screenshots`:

- структура: ровно два раздела, нет подразделов и рабочего стола, рабочая
  область без карточек, показателей и демоданных, заголовок соответствует
  разделу, активен ровно один пункт;
- логотипы: светлый и тёмный варианты из переданных файлов, белые буквы и слоган
  видны полностью, белого прямоугольника и обрезанных частей нет, пропорции не
  искажены;
- темы и декор: переключение меняет палитру, логотип и декор, выбор сохраняется
  после перезагрузки, вспышки нет, у тёмного декора нет прямоугольных границ,
  в светлой теме нет тёмной подложки и неонового свечения, декор не блокирует
  нажатия и не создаёт прокрутку;
- поведение и адаптация: проверены целевые размеры, меню и переключатель
  доступны на каждом размере, подпись `Service Desk` не обрезается, переключение
  разделов не сбрасывает тему, работают прямые маршруты, обновление и история,
  Tab перемещает фокус в понятном порядке, ошибок в консоли и отсутствующих
  картинок нет.
